# 需求分析

## 1. 项目目标

MedPharm RAG Assistant 的核心任务是把 7 本医学教材压缩为不超过原始内容 30% 的高价值知识精华，同时保留教学连贯性，并提供可追溯来源的 RAG 精准问答能力。系统不是简单摘要工具，而是面向医学教学场景的知识整合智能体：需要识别重复知识、合并同义表达、保留关键前置依赖，并把整合结果组织为可学习、可检索、可追溯的结构化知识体系。

## 2. 问题分解

“7 本教材压缩到 30%”可以拆解为以下子问题：

1. **教材解析问题**：不同教材可能来自 PDF、TXT、Markdown、DOCX 等格式，章节结构、页眉页脚、页码、标题样式不一致。系统需要将原始文件解析为统一的结构化 JSON，包括教材、章节、页码、正文和字数信息。
2. **知识点抽取问题**：医学教材篇幅长、术语密集，不能以自然段为最小单位直接整合。系统需要从章节中抽取概念、定理、方法、现象等知识点，并保留定义、分类、章节和页码来源。
3. **跨教材对齐问题**：同一医学知识可能在不同教材中以不同名称出现，例如“白细胞”“白血细胞”“leukocyte”。系统需要判断这些表达是否语义等价或高度重叠。
4. **重复与冗余压缩问题**：多本教材会重复讲解基础概念。系统需要将重复知识合并或删除冗余副本，同时保留最完整、最准确、最适合教学的版本。
5. **教学路径保持问题**：医学知识存在前置依赖，例如“炎症介质”依赖“炎症反应”，“药代动力学参数”依赖“吸收、分布、代谢、排泄”。压缩不能破坏学习顺序。
6. **RAG 问答问题**：压缩后的知识需要支持精准检索和问答，回答必须基于教材上下文，并能引用教材、章节、页码和原文片段。
7. **可解释评审问题**：竞赛评分不仅看结果，还看设计依据。系统需要提供压缩比、整合决策、检索策略和 Agent 架构的可解释说明。

## 3. 知识点粒度定义

本项目将“知识点”定义为一个可以被独立学习、检索和整合的最小教学单元，粒度控制在“一句话能说清核心含义”的级别。知识点过大会降低对齐精度，过小会破坏语义完整性。

知识点主要包括四类：

| 类型 | 定义 | 示例 |
|---|---|---|
| 概念 | 对医学名词、结构、过程或疾病的定义 | 白细胞是参与机体免疫防御的一类血细胞 |
| 定理/规律 | 教材中稳定成立的机制、原则或规律 | 药物半衰期与清除率和表观分布容积相关 |
| 方法 | 诊断、实验、治疗、给药或分析步骤 | 革兰染色用于区分革兰阳性菌和阴性菌 |
| 现象 | 病理、生理、药理或微生物学现象 | 炎症局部可出现红、肿、热、痛和功能障碍 |

粒度控制原则：

1. 一个知识点只表达一个核心判断，不混入多个并列主题。
2. 知识点应包含必要限定条件，例如适用范围、对象和关键机制。
3. 对定义类内容，保留“是什么”；对机制类内容，保留“为什么”；对方法类内容，保留“怎么做”和“何时用”。
4. 若一个段落包含多个并列概念，应拆分为多个知识点。
5. 若一个概念必须依赖上下文才能理解，应在图谱中保留前置关系，而不是把全部上下文塞进单个知识点。

## 4. 重复判定标准

重复知识不是只看字面相同，而是看语义是否等价、内容是否高度重叠、教学功能是否一致。系统采用两级判定：

### 4.1 语义等价

满足以下条件之一可判定为语义等价候选：

1. 中文同义表达：白细胞 = 白血细胞。
2. 中英文术语对应：白细胞 = leukocyte。
3. 专业缩写与全称对应：ADME = 吸收、分布、代谢、排泄。
4. 表述角度不同但医学指向一致：粒细胞减少症 = 外周血中性粒细胞绝对值低于正常范围。

语义等价候选仍需结合上下文判断，避免同名异义。例如“休克”在病理生理学和临床诊断章节中的侧重点不同，不能仅因名称相同就完全合并。

### 4.2 内容高度重叠

若两个知识点的定义、机制、适用范围和教学用途高度一致，且文本相似度或语义相似度超过 85%，判定为高度重复。项目采用“>85% 相似度”作为重复合并阈值，原因是医学教材中常见轻微措辞差异，但关键语义通常稳定。

重复判定结果分为三类：

| 判定结果 | 标准 | 处理 |
|---|---|---|
| 完全等价 | 术语和定义均等价，差异仅为措辞 | merge，保留更完整版本 |
| 高度重叠 | 相似度 >85%，核心内容相同但细节略有差别 | merge，合并补充细节 |
| 相关但不重复 | 同一主题下角度不同或层级不同 | keep，并建立关系边 |

## 5. 教学连贯性保障

压缩的核心风险是删除了后续学习所需的前置知识。为避免学习路径断裂，系统通过知识图谱保留依赖关系，并在整合时优先保护前置节点。

教学连贯性保障策略：

1. **保留前置依赖**：若知识点 A 是理解知识点 B 的前提，则即使 A 在多本教材重复出现，也必须至少保留一个完整版本。
2. **保留章节层级**：知识点仍关联原教材章节和页码，避免压缩后脱离教学语境。
3. **区分重复和依赖**：例如“免疫反应”和“炎症反应”高度相关，但不是重复关系，应建立 prerequisite 或 applies_to 边，而不是合并。
4. **合并不删除来源**：merge 后的知识点保留所有来源教材、章节和页码，方便教师检查。
5. **学习路径校验**：整合后对图谱进行依赖检查，若某个节点的前置节点全部被 remove，则触发风险提示或改为 keep。

## 6. 压缩比计算方式

压缩比用于衡量整合效果，定义为：

```text
压缩比 = 整合后总字数 / 原始总字数
```

其中：

1. 原始总字数：7 本教材解析后正文内容的总字符数，不包含页眉页脚、页码、目录噪声。
2. 整合后总字数：merge、keep 后保留的知识点定义、补充说明和必要上下文的总字符数。
3. remove 的冗余副本不计入整合后总字数。
4. 目标压缩比：≤ 30%。

压缩比不是唯一指标。若过度压缩导致前置知识丢失或 RAG 回答不可追溯，则视为失败压缩。因此系统同时输出 merge_count、keep_count、remove_count、compression_ratio 和典型整合案例。

## 7. RAG 分块策略选择依据

RAG 分块需要在上下文完整性和检索精度之间平衡。本项目采用 **600 字/chunk + 100 字重叠** 的滑动窗口策略。

### 7.1 为什么选择 600 字

医学知识点通常由术语定义、机制解释、临床意义或示例组成，平均长度约 200-400 字。600 字 chunk 通常可以完整包含 1-2 个相关概念，既能保留上下文，又不会把过多无关知识混入同一个检索单元。

若 chunk 太小，检索结果可能只包含定义的一半，生成阶段缺少判断依据。若 chunk 太大，向量表示会被多个主题稀释，导致检索命中看似相关但回答证据不集中。

### 7.2 为什么选择 100 字重叠

教材知识点经常跨段落或跨页延续。100 字重叠可以降低知识点在 chunk 边界被截断的风险，使定义、限定条件和结论至少在相邻 chunk 中有一次完整出现。

### 7.3 分块大小对比

| Chunk 大小 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 300 字 | 关键词精度高，噪声少 | 医学概念容易被切断，上下文不足 | 不适合作为主策略 |
| 600 字 | 可覆盖 1-2 个概念，检索精度与上下文平衡 | 对极长机制仍需多 chunk 支持 | 作为默认策略 |
| 800 字 | 上下文更完整 | 单个向量包含主题增多，精度下降 | 可作为长章节备选 |
| 1200 字 | 章节语境充分 | 向量语义严重稀释，召回结果不聚焦 | 不推荐 |

## 8. Embedding 模型选择

候选模型包括 BGE-small-zh-v1.5、paraphrase-multilingual 和 OpenAI Ada。最终选择 **BGE-small-zh-v1.5**。

| 模型 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| BGE-small-zh-v1.5 | 中文优化，本地免费，512 维，部署成本低 | 对少量医学专有缩写仍需 LLM 复核 | 采用 |
| paraphrase-multilingual | 多语言通用，开源可本地运行 | 中文医学语义匹配弱于中文专用模型 | 备选 |
| OpenAI Ada | 通用语义效果强，维护成本低 | 需联网与付费，数据出境和比赛环境不稳定 | 不作为默认 |

选择 BGE 的理由：

1. 中文教材场景优先，中文语义对齐效果比通用多语言模型更稳定。
2. 本地运行，无 API 成本，不受网络和额度限制。
3. 512 维向量在效果、存储和检索速度之间平衡，适合嵌入式 ChromaDB。
4. 可与 LLM 精确验证形成双重对齐策略，降低医学术语误判。
