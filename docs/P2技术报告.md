# RAG 分块策略优化：基于医学教材的实验对比报告

## 摘要（Abstract）

本文针对医学教材知识整合场景，系统性地对比了不同 RAG 分块策略和检索方案对检索命中率的影响。通过在 6 本医学教材（局部解剖学、生理学、医学微生物学、病理学、传染病学、病理生理学）上构建包含 20 道评测题的自建 Benchmark，实验对比了 300字、600字、800字三种 chunk size 在纯向量检索和混合检索（向量+BM25+RRF）下的表现。结果表明：600字 chunk size + 混合检索方案在医学教材场景下取得最优的命中率-效率平衡，命中率@5 达到 85%，比纯向量检索提升 15 个百分点，平均响应时间仅增加 0.3 秒。本文还探讨了双重语义对齐策略（Embedding初筛+LLM验证）在跨教材知识点去重中的效果。

**核心发现：**
- 600字 chunk + 混合检索命中率@5 = 85%（vs 纯向量 70%）
- 混合检索相比纯向量提升 15 个百分点，额外耗时仅 0.3s
- 双重语义对齐（Embedding 0.85 + LLM 验证）相比纯 Embedding 减少 80% 误合并

## 1. 问题分析（Problem Statement）

### 1.1 背景

在高校医学教育中，同一学科往往存在多本教材并行使用。这些教材内容高度重叠但表述各异，给学生和教师带来困扰。本项目的目标是用 AI 将 7 本医学教材压缩到原始体量 30% 以内，同时保证教学完整性。

### 1.2 RAG 检索的核心挑战

医学教材的 RAG 检索面临三个独特挑战：

**挑战1：术语密集且精确**
- 医学概念定义精确，一个关键词的差异可能改变含义
- 例如"动作电位"和"静息电位"仅一字之差，但代表完全不同的概念
- 纯语义检索容易混淆相似但不同的术语

**挑战2：跨教材表述差异**
- 同一概念在不同教材中可能用不同术语描述
- 例如"白细胞"和"白血细胞"和"leukocyte"指同一概念
- 需要语义理解而非精确匹配

**挑战3：上下文完整性需求**
- 医学知识点的定义往往需要完整的段落上下文
- chunk 过小会截断定义，过大会稀释相关性
- 需要在精度和上下文之间找到平衡点

### 1.3 现有方案的瓶颈

| 方案 | 优势 | 劣势 |
|------|------|------|
| 纯向量检索 | 语义理解好，能处理同义词 | 精确术语匹配差，相似概念易混淆 |
| 纯 BM25 检索 | 关键词匹配精确 | 无法理解语义，同义词检索失败 |
| 固定 chunk size | 实现简单 | 无法适应不同长度的知识点定义 |

### 1.4 本文的改进方案

提出 **600字 chunk + 混合检索（向量+BM25+RRF）** 方案：
- 600字 chunk 平衡精度和上下文完整性
- 向量检索处理语义匹配
- BM25 检索处理精确术语匹配
- RRF（Reciprocal Rank Fusion）融合两种检索结果

## 2. 方案设计（Proposed Approach）

### 2.1 分块策略

采用滑动窗口分块，参数化 chunk_size 和 overlap：

```
分块算法：
input: text, chunk_size, overlap
output: list of chunks with metadata

for i in range(0, len(text), chunk_size - overlap):
    chunk = text[i : i + chunk_size]
    metadata = {textbook, chapter, page, chunk_index}
    yield {content: chunk, metadata: metadata}
```

三种配置对比：

| 策略 | chunk_size | overlap | 理由 |
|------|-----------|---------|------|
| 小块 | 300字 | 50字 | 精度高，但上下文可能不足 |
| 中块 | 600字 | 100字 | 平衡精度和上下文（推荐） |
| 大块 | 800字 | 150字 | 上下文足，但精度可能下降 |

选择 600字的依据：
1. 医学概念平均解释长度约 200-400 字，600 字通常能完整包含 1-2 个概念
2. 100 字重叠可以防止定义在 chunk 边界被截断
3. 600 字不会像 800+ 字那样把多个无关主题混入同一向量

### 2.2 Embedding 模型选择

| 模型 | 维度 | 中文支持 | 本地运行 | 推理速度 |
|------|------|----------|----------|----------|
| BGE-small-zh-v1.5 | 512 | ✅ 优化 | ✅ | ~50ms/chunk |
| paraphrase-multilingual-MiniLM-L12-v2 | 384 | ⚠️ 通用 | ✅ | ~30ms/chunk |
| OpenAI text-embedding-3-small | 1536 | ✅ | ❌ 需API | ~200ms/chunk |

选择 **BGE-small-zh-v1.5**：
- 专门针对中文优化，医学术语覆盖更好
- 512 维度适合本地存储和快速检索
- 本地免费运行，避免比赛网络和 API 成本风险
- sentence-transformers 库支持，部署简单

### 2.3 检索策略

**纯向量检索：**
```
query_embedding = embed(query)
top_k = vector_db.search(query_embedding, k=10)
return top_k[:5]
```

**混合检索（本文方案）：**
```
vector_results = vector_db.search(query_embedding, k=10)
bm25_results = bm25_index.search(query, k=10)
fused = reciprocal_rank_fusion(vector_results, bm25_results, k=60)
return fused[:5]
```

**RRF 融合算法：**
```
RRF_score(d) = Σ 1 / (k + rank_i(d))
其中 k=60（经验值），rank_i 是文档 d 在第 i 个检索器中的排名
```

### 2.4 双重语义对齐

跨教材知识点去重采用两层策略：

```
第一层：Embedding 余弦相似度初筛
  - 对所有知识点名称+定义进行向量化
  - 计算余弦相似度
  - 相似度 ≥ 0.85 的节点对进入候选集

第二层：LLM 精确验证
  - 对候选对调用 LLM 判断是否真正等价
  - 输出 {is_equivalent: bool, reason: str}
  - 只有 LLM 确认等价的才执行合并
```

## 3. 实验与结果（Experiments & Results）

### 3.1 实验环境

- **硬件**: WSL2, 16GB RAM, CPU-only
- **模型**: mimo-v2-flash（LLM）, BGE-small-zh-v1.5（Embedding）
- **向量库**: ChromaDB（嵌入式）
- **教材**: 6 本医学教材（局部解剖学、生理学、医学微生物学、病理学、传染病学、病理生理学）

### 3.2 评测集构建

自建 RAG Benchmark，包含 20 道评测题：

| 题型 | 数量 | 示例 |
|------|------|------|
| 事实性 | 8 | "什么是动作电位？" |
| 比较性 | 6 | "有丝分裂和减数分裂有什么区别？" |
| 跨教材 | 6 | "炎症在病理学和生理学中分别是如何描述的？" |

每题标注：预期答案、来源教材、来源章节。

### 3.3 实验1：分块策略对比

固定检索方式为混合检索，对比不同 chunk_size 的命中率：

| chunk_size | 命中率@5 | 平均响应时间 | Token/查询 | 说明 |
|-----------|----------|-------------|-----------|------|
| 300字 | 75% | 1.5s | 850 | 上下文不足，部分定义被截断 |
| **600字** | **85%** | **1.6s** | **1300** | **最优平衡** |
| 800字 | 80% | 1.8s | 1700 | 精度下降，无关内容稀释相关性 |

**结论**: 600字 chunk 在命中率和效率之间取得最优平衡。300字因为截断导致命中率低，800字因为精度下降导致命中率略低。

### 3.4 实验2：检索策略对比

固定 chunk_size=600字，对比不同检索方式：

| 检索方式 | 命中率@5 | 平均响应时间 | 说明 |
|----------|----------|-------------|------|
| 纯向量 | 70% | 1.3s | 语义匹配好，但精确术语差 |
| 纯 BM25 | 65% | 1.1s | 关键词匹配好，但语义理解差 |
| **混合（RRF k=60）** | **85%** | **1.6s** | **兼顾语义和关键词** |

**结论**: 混合检索相比纯向量提升 15 个百分点，相比纯 BM25 提升 20 个百分点。额外耗时仅 0.3s，在可接受范围内。

### 3.5 实验3：双重语义对齐效果

对比单层 Embedding 对齐和双重对齐（Embedding+LLM）：

| 对齐方式 | 准确率 | 召回率 | F1 | 误合并数 |
|----------|--------|--------|-----|---------|
| 纯 Embedding (≥0.85) | 75% | 90% | 82% | 8 |
| **双重对齐** | **95%** | **88%** | **91%** | **1** |

**结论**: 双重对齐将误合并数从 8 降到 1（减少 87.5%），虽然召回率略降 2%，但准确率大幅提升。在医学场景下，准确性比召回率更重要。

### 3.6 实验4：Token 消耗分析

| 操作 | 平均 Token/次 | 总调用次数 | 总 Token |
|------|-------------|-----------|---------|
| 知识点提取 | 1500 | ~50 | ~75,000 |
| 关系抽取 | 800 | ~50 | ~40,000 |
| 语义对齐 | 600 | ~20 | ~12,000 |
| RAG 问答 | 1300 | ~20 | ~26,000 |
| **总计** | — | ~140 | **~153,000** |

使用 mimo-v2-flash 模型，总处理时间约 6 分钟。

## 4. 局限性与未来方向（Limitations & Future Work）

### 4.1 已知局限

1. **评测集规模小**: 20 道题不足以得出统计显著结论，需要扩充到 50+ 道
2. **未测试 Rerank**: 未引入二次排序模型（如 bge-reranker），预计可再提升 5-10%
3. **单模型对比**: 只测试了 BGE-small-zh，未对比 BGE-large-zh 或其他模型
4. **chunk size 粒度粗**: 只测试了 3 个值，未做更细粒度的搜索

### 4.2 未来方向

| 方向 | 优先级 | 预计收益 |
|------|--------|----------|
| 引入 Rerank 二次排序 | P1 | 命中率 +5-10% |
| 扩充评测集到 50+ 道 | P1 | 实验结论更可靠 |
| 测试 BGE-large-zh | P2 | Embedding 质量提升 |
| 自适应 chunk size | P2 | 根据内容密度动态调整 |
| 引入知识图谱辅助检索 | P2 | 利用实体关系提升检索精度 |

---

## 5. 结论

在医学教材 RAG 场景下，推荐配置：

| 参数 | 推荐值 | 理由 |
|------|--------|------|
| Chunk size | 600字 | 命中率最优（85%） |
| Overlap | 100字 | 防止边界截断 |
| Embedding | BGE-small-zh-v1.5 | 中文优化，本地免费 |
| 检索方式 | 混合检索（向量+BM25+RRF k=60） | 兼顾语义和关键词 |
| Top-K | 5 | 平衡召回和精度 |
| 语义对齐 | 双重（Embedding 0.85 + LLM 验证） | 减少 87.5% 误合并 |

该方案在 20 道评测题上达到 85% 的命中率@5，平均响应时间 1.6 秒，总 Token 消耗约 153,000。
